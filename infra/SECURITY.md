# Backend security and trust boundary

Only the trusted gateway may hold credentials for protected tools. Agents receive neither the demo connector secret nor direct network access to the demo service. Calling `/v1/decisions/evaluate` alone is advisory. Its ALLOW response is not a credential, and bypassing the gateway bypasses protection. A trusted machine connector must have a server-managed connector flag, execution role and a live scoped delegation. Human approvers must authenticate with a separately provisioned HUMAN principal and the required server-managed role. The local signer is a development convenience, not a production identity provider.

JWT verification pins RS256, issuer and audience, requires subject/issued-at/expiry, verifies the signature and rejects expired or future-issued credentials. Token tenant and role claims are ignored. Identity maps `(issuer, subject)` to one database principal. Every authorization mutation rechecks the database identity snapshot and delegation. Grants use exact action and resource-type matches; unsupported wildcard grants fail closed. SQL uses bound parameters, tenant-scoped predicates and composite foreign keys. Tenant isolation is enforced by application queries and relational constraints; this release does not claim PostgreSQL row-level security against a compromised runtime process.

Policy evaluation receives server-resolved resource metadata, not caller-supplied sensitivity or counts. Caller context remains explicitly untrusted. Missing metadata stays absent so the canonical engine must handle it conservatively. No body claim becomes an identity, role or delegation. Policy engines are trusted modules; an asynchronous evaluation deadline cannot preempt arbitrary synchronous JavaScript that blocks the event loop. The canonical engine's own computation budget is therefore required in production.

Evaluation idempotency is scoped to tenant, principal, operation and request ID. Conflicting bodies return 409. Approvals are joined to immutable decisions, and resolution requires the canonical binding digest the human reviewed. Policy version, expiry and required authority are additionally stored server-side. Execution recomputes the digest from the actual arguments, verifies the entire original request, re-evaluates the current policy, checks expiry and approvals, consumes the approval and creates a unique execution attempt within one transaction. Tenant locks serialize authorization transitions; updates and audit inserts either commit together or roll back together.

The database claim commits before outbound I/O. There is no general exactly-once guarantee across a database and a remote service. A crash can leave a claim with no side effect or with an unacknowledged side effect. The isolated demo service also enforces execution-ID idempotency. Uncertain delivery becomes UNKNOWN and requires reconciliation. Adapter response bodies are discarded and never become authorization instructions. Caller cancellation and adapter deadlines bound outbound work; a disconnect cannot prove that an already transmitted operation did not occur.

The only shipped adapter creates synthetic notes at a fixed configured hostname/path. Agent arguments cannot select a hostname, URL, redirect, method or header. The adapter rejects credentials in URLs, unexpected hostnames, path/query changes and redirects. Compose keeps the tool off host ports and on a private network; its database role cannot connect to the authorization database. API and gateway also have a host-facing bridge for loopback access; Compose is not a production egress firewall. Production connectors require explicit destination allowlists, network egress policy, TLS/mTLS and service-specific idempotency/reconciliation before real customer systems are enabled. No arbitrary shell or URL proxy exists.

Runtime SQL roles can append decisions, policy snapshots, approval actions and audit events, but cannot update/delete them or disable their triggers. Migrations run as a separate owner. Database owners/superusers, backup operators and host administrators remain inside the trust boundary. SHA-256 chains detect accidental or unauthorized edits against a trusted head; a database administrator can disable triggers and rewrite records and heads. No independent WORM anchor or external checkpoint is implemented. Public event hashes follow the canonical `aegis.audit-event/v1` domain separation; operational evidence uses a separate internal chain. Export signed head checkpoints to an independently administered archive before claiming protection against administrator rewriting or tail truncation.

Tool arguments are digested, not retained in decisions/audit/idempotency records. Audit metadata contains identifiers, reason codes and digests, not credential values, request bodies or remote response bodies. Approval comments and policy documents are application data with tenant-scoped access, not secrets storage. The demo database stores synthetic note text as its actual side effect. Avoid sensitive identifiers in resources. Logs and spans omit bodies and authentication headers. Authentication errors without a verified tenant go to the system evidence chain and cannot be listed by tenant callers.

No encrypted payload storage or application encryption key is implemented. Deployments must supply PostgreSQL transport security, encrypted disks/backups and encryption-key ownership through their infrastructure. IdP signing keys belong to the IdP; HTTPS JWKS cache lifetime is sixty seconds and rotations need overlap or explicit restart/cache invalidation. The cursor HMAC key belongs to the deployment's secret manager, must be shared across replicas and should rotate by restarting replicas together (old cursors become invalid). Connector secrets belong only to the gateway and tool service; rotate both together and revoke affected pending authorizations. No secret values live in database connector metadata.

Global authenticated rate buckets are stored in PostgreSQL (120 requests/principal/minute). An additional local IP limit bounds unauthenticated traffic. Production needs ingress-wide unauthenticated throttling and trusted proxy configuration. Per-tenant locking favors correctness over hot-tenant throughput; measure before replacing it with finer-grained locks. Audit retention, signed external anchors, disaster-recovery drills, SSO provisioning, production connector secret rotation and customer-facing administration remain deployment/integration work.
